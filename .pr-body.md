## Problem

- New pi sessions on M-02877 warn `Chorus plugin: not configured` and `chorus: failed: Failed to resolve MCP server "chorus" header "Authorization" from environment variable: CHORUS_API_KEY`. secretspec cannot decrypt `secretspec.age`: `age-plugin-se` fails with OSStatus -25308 (errSecInteractionNotAllowed), because macOS reports the data-protection keybag locked (`MKBGetDeviceLockState` = 1) while the screen and the login keychain are unlocked. The zsh export of `CHORUS_API_KEY` had no fallback. Only `chorus-pi-daemon` had one, its cache.
- herdr panes start with the herdr server's environment, which dated from 2026-09-30 and included `__HM_SESS_VARS_SOURCED=1`. Home Manager's guard then skipped the current `hm-session-vars.sh`, so panes had no `SIGNET_*`, and pi fell back to the personal Signet daemon on 3850 as agent `default`, not team Signet. Restarting WezTerm does not help, because herdr keeps its server.
- The personal Signet container ran 0.232.1, while its create-time pin said 0.214.27. The host `signet` CLI comes from that container, so `signet connect pi` could not install the pi extension fix for Signet-AI/signetai#2077.
- `launchctl bootout` of `com.dktaohan.signet-container` stopped the podman VM, and the Gas City container with it. The agent's script starts the VM, so vfkit and gvproxy keep the job's process group.
- The `chorusCli` activation check runs `chorus --version` without Node on PATH. The CLI is a `#!/usr/bin/env node` script, so the check always failed, and every switch reinstalled 795 packages.
