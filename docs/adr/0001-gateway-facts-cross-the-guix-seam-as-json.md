# ADR 0001 — Gateway facts cross the Guix seam as hand-written JSON

- Status: accepted
- Date: 2026-08-01
- Bead: `home-manager-0pr.2`
- Supersedes: nothing

## Context

Four modules each held the complete set of facts about how an agent reaches a
model, and they had already drifted:

| site | held |
|---|---|
| `modules/M-02877/darwin.nix` | headroom `18787:8787`, `HEADROOM_MODE=cache`, phoenix, local-model-proxy |
| `modules/M-02877/dktaohan.nix` | pi's `models.json`, direct to `…/anthropic` |
| `guix/home-configuration.scm` | headroom `127.0.0.1:8787:8787`, **no `HEADROOM_MODE`** |
| `modules/doom.d/…/agent-shell/config.el` | `http://127.0.0.1:8787` |

The drift was not hypothetical. `HEADROOM_MODE=cache` carried a five-line
rationale on darwin and was simply absent under Guix Home, so mahakala silently
ran headroom's built-in default mode — no error, just a different cost and
cache-hit tradeoff.

Two genuine adapters for the same interface already existed (a launchd adapter
on darwin, a shepherd/OCI adapter under Guix Home), so the seam was real. What
was missing was the interface they should both satisfy.

The hard constraint: **`guix/home-configuration.scm` is Scheme and cannot
import Nix.** Any fact shared across that seam has to be duplicated or cross as
data.

## Decision

A hand-written `gateway.json` at the repo root is the single owner. Both
substrates read it:

- Nix reads it in `modules/gateway.nix`, which parses it once, derives the
  values consumers would otherwise re-derive (full URLs, per-entity publish
  specs, the key-lookup command), and injects the result as the `gateway`
  module argument. Every Nix consumer is a thin adapter over that.
- Guile reads it directly in `guix/home-configuration.scm` via guile-json.

Published ports are keyed by **entity** (`M-02877`, `mahakala`) rather than by
substrate, because the difference is per-machine: 8787 is container-internal
only on M-02877, where it is published as 18787, but is also the host port on
mahakala. Keying by entity puts both readings side by side in one file instead
of requiring a reader to already know which machine they are on.

`gateway.json` holds no secret — only the *name* of one. The key crosses to
consumers as a **command** that prints it at agent-process start.

## Alternatives rejected

**Nix owns the facts and generates a file for Guix, gated by `just check`.**
Rejected as strictly more machinery for the same guarantee. It adds a committed
derived artifact plus a new gate to detect drift in that artifact, where a
hand-written file has no derived copy to drift from. It also inherits a deploy
ordering hazard: `just deploy-mahakala` runs `guix home reconfigure` *before*
`home-manager switch` (`Justfile:11-17`), so a file generated by Home Manager
is read stale by Guix on the first deploy after any change.

**Deliberate duplication with paired breadcrumb comments**, the existing
`kubernetes-helm`/`kind` precedent (`modules/workstation.nix:38-39` +
`guix/home-configuration.scm:58-59`). Rejected here because that precedent
covers a *package list*, where divergence is visible the moment a command is
missing. This is addressing: divergence is silent and produces a wrong cost
profile rather than an error, which is exactly the failure that already
happened with `HEADROOM_MODE`.

**Home Manager takes over headroom on mahakala, deleting the Scheme copy.**
This would have removed the seam rather than crossing it, and was the most
attractive option on paper. It is infeasible: mahakala runs Guix System, which
is shepherd-based, so Home Manager's `systemd.user` services have no init to
attach to, and headroom depends on `rootless-podman-service-type` from
`guix/system.scm:261-270`. Recorded here because a future reviewer would
otherwise re-litigate it. `home-manager-0pr.9` tracks Guix/HM ownership per
concern more broadly.

## Consequences

- Each of `baseUrl`, every port, the headroom image, and `HEADROOM_MODE` is
  written once and read everywhere else.
- `HEADROOM_MODE=cache` now applies on mahakala too. **This is a behaviour
  change on that machine** — it previously ran headroom's default mode. It
  takes effect on the next `guix home reconfigure`.
- JSON cannot carry comments, so rationale lives in `modules/gateway.nix`, in
  `guix/home-configuration.scm`, and in `CONTEXT.md`. Facts are not duplicated;
  explanations deliberately are, on both sides of the seam.
- `rg -n '18787|8787|genai.thelegogroup'` now returns `gateway.json` as the only
  owner plus reads. The literals no longer appear in any shell string.
- A typo in a key name raises from `gateway-ref` instead of quietly putting
  `#f` into a container's environment.

## How this was verified

`just check` never evaluates the Guix files, and there is no `guile` or `guix`
on the darwin workstation, so the Guix half of this change would normally be
unverifiable until someone reconfigured mahakala. It was verified instead by
running real Guix in a container
([`registry.gitlab.com/debdistutils/guix/container:latest`](https://gitlab.com/debdistutils/guix/container),
arm64, Guix 1.5.0) and rendering the actual record out of this repo's
`home-configuration.scm`:

- `(use-modules (json))` resolves under Guix's own Guile — the main risk of
  this decision.
- Guix's guile-json decodes JSON objects to **alists**, not hash tables. The
  first draft used `hash-ref` and would have crashed `guix home reconfigure`.
  `gateway-object-ref` now accepts either representation.
- `oci-container-configuration->options` renders
  `-p 127.0.0.1:8787:8787` and the same `--env` set as before.
- Diffing the rendered record against the pre-change file shows exactly one
  added line, `HEADROOM_MODE=cache`, and no other difference.

Reproduce with the commands in `docs/solutions/proxy-chain-and-harness-auth.md`.
